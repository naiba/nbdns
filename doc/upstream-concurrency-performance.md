# 上游并发与 DoH 连接复用验证

原始压测目录已在 v2.0.3 发布准备时按要求清理；下文的本地路径及文件名仅用于说明数据来源。汇总结果、回归测试与复现工具保留在仓库。

本次基线包含 singleflight，候选增加回源并发上限、竞速取消和 DoH 连接复用调整。nbDNS 的入站 TLS 仍由前端代理负责；代码没有增加证书配置或 HTTPS 监听。本地 TLS 证书仅用于模拟 HTTPS 上游，客户端正常验证证书。

## 先复现，再修复

- 支持 HTTP/2 的测试上游，在旧自定义 DialContext 下实际收到 HTTP/1 请求；修复后协商 HTTP/2。
- 两轮各 8 个并发请求，旧配置创建 14 条连接；修复后共创建 8 条并复用。DNS ID、question、RCODE、答案地址均校验。
- 快上游返回有效答案后，旧代码没有取消慢 DoH 请求；修复后服务端观察到请求取消。
- UDP/TCP 阻塞读取在取消后及时退出；取消的池连接被丢弃，后续请求正常。成功归还连接后再取消原 context，不影响池内连接。
- 回源名额满时返回 SERVFAIL；缓存命中不占名额，符合条件的过期缓存仍可降级。请求结束后名额恢复。

`max_concurrent_queries` 默认 64，限制等待回源的客户端请求数，包含 singleflight 等待者。它不是 QPS 限流，也不限制缓存命中、本地记录或过滤响应。TCP/DoT 连接池的建连接口不接受请求 context，已经开始的池建连仍受现有连接数和建连超时约束；已取得连接的读写可被取消。UDP 取消释放本地 socket，不能撤回已发送到远端的数据包。

## 本地 HTTPS 对照

以下性能测量使用调整前的默认并发上限 256；随后默认值按路由器使用场景改为 64，未重新运行该性能矩阵。

真实 nbDNS 二进制、UDP 客户端、本地 HTTPS 上游，目标和生成器各 GOMAXPROCS=2。每组 3 秒、三次重复，组间冷却 3 秒；每次使用唯一域名，避免 singleflight 掩盖连接成本。按版本顺序测量，未交错随机化，结果不代表公网或路由器容量。

| 并发 | 修改前 QPS | 修改后 QPS | 修改前 P99 ms | 修改后 P99 ms |
| --- | ---: | ---: | ---: | ---: |
| 1 | 2118 | 2198 | 3.491 | 2.985 |
| 16 | 342 | 2937 | 132.848 | 26.430 |
| 64 | 182 | 4311 | 1153.964 | 50.310 |

均为三次中位数，18 组响应校验错误为零。这组 HTTPS 模拟上游使用 HTTP/1，主要验证连接复用收益；HTTP/2 协商由独立测试验证。

产物位于 `/root/nbdns-performance/upstream-concurrency/`：`https-unique-before.jsonl`、`https-unique-after.jsonl` 及同名目录中的日志与性能数据。使用相同域名的早期探索压测受 singleflight 影响，其中一次被会话中断，均不纳入性能比较。

复现时使用 `cmd/dnsperf` 的 `-scenario upstream_https -unique-queries -duration 3s -concurrency 1,16,64 -repeat 3 -cooldown 3s`，每次指定新的输出目录。独立构建未带版本号的二进制，以禁用自动更新。

## UDP 对照与检查

同样使用唯一名称、每组 3 秒、三次重复的 UDP 对照，12 组响应校验错误为零。

| 并发 | 修改前 QPS | 修改后 QPS | 修改前 P99 ms | 修改后 P99 ms | 修改前/后 CPU µs/请求 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 16 | 3756 | 3580 | 28.941 | 27.634 | 94.6 / 95.4 |
| 64 | 4544 | 5369 | 48.859 | 46.125 | 82.1 / 84.7 |

吞吐变化分别约为 -4.7% 和 +18.2%，CPU/请求略有增加。未证明普通 UDP 有一致收益；取消机制增加的 context 和回调成本也不能忽略。原始结果为 `udp-unique-before.jsonl`、`udp-unique-after.jsonl`。

全仓 `go test -race ./...`、`go vet ./...`、`go build ./...` 和 `git diff --check` 均通过。测试只使用本机模拟上游，没有操作前端代理、路由器或公网解析服务。

最终 DoT 链路检查使用唯一名称、16 并发、1 秒，共 11,676 次请求，上游同样收到 11,676 次，响应校验错误为零。证书仅由本地测试上游提供，子进程通过测试 CA 正常验证；此检查不用于性能前后比较。结果为 `dot-validation.jsonl`。
